# 系统化调试

出现失败后，不要立即猜测或重写模块。按以下方式处理：

1. 读取错误类型、文件、行号、调用栈和命令退出状态。
2. 确认失败能够稳定复现，并找出触发它的最小场景。
3. 对照最近修改、类型定义、调用点和数据形态定位根因。
4. 一次只实施能够验证当前假设的最小修复。
5. 重新运行原本失败的检查。
6. 如果出现新失败，以新证据开始下一轮分析。

修复语法或导入问题后，继续执行原计划中的业务测试；“可以导入”不代表业务已经正确。

禁止通过吞掉异常、删除测试、放宽正确断言或进行无关重构掩盖失败。

没有重新验证时，只能说明实施了修复，不能声称问题已经解决。
