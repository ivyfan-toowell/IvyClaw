# 测试驱动开发

开始编码前，从需求、现有接口和测试中提取本次任务的可验证行为。

按照以下循环实施：

1. 编写一个能够证明目标行为的测试。
2. 在具备执行能力时运行该测试，确认它因目标行为尚未实现而失败。
3. 编写使测试通过的最小实现。
4. 再次运行测试，确认目标行为通过。
5. 只进行与当前任务相关的整理，并在整理后重新测试。

新增测试应覆盖正常路径，以及与任务直接相关的边界或异常场景。测试接口时，确保测试请求结构与路由声明一致，并验证真实对外响应契约。

如果环境或工具不支持执行测试，仍应编写测试，但必须明确标记为“尚未运行”，不得把测试文件的存在当作通过证据。

不得通过删除有效测试、降低断言标准或改变正确业务预期让测试通过。
