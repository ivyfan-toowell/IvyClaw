# 单元测试编写规范

## 框架与结构

* 使用 `pytest`。
* 测试文件命名为 `test_<module>.py`，统一放在 `tests/` 目录下。
* 一个测试函数只验证一个明确行为或场景。
* 测试代码按 Arrange-Act-Assert 思路组织：

  * Arrange：准备测试数据和依赖。
  * Act：执行被测试函数或接口。
  * Assert：验证结果。
* 优先复用已有 fixture，不重复创建相同测试准备逻辑。

## 命名

* 测试函数使用 `test_` 开头。
* 名称应清楚描述“测试对象 + 场景 + 预期行为”。
* 示例：`test_calc_order_total_with_multiple_items`。
* 避免使用 `test1`、`test_case` 等无法表达测试目的的名称。

## 覆盖要点

* 至少覆盖正常路径。
* 根据业务需要覆盖边界情况，例如空列表、`qty=0`、最小值、最大值。
* 覆盖常见非法输入和错误路径。
* 使用 `pytest.raises` 验证预期异常。
* 对 FastAPI 接口测试时，至少验证状态码和关键响应字段。
* 不只验证“代码能运行”，还要验证返回结果是否符合业务预期。

## Mock 与依赖

* 外部数据库、HTTP 请求、第三方服务等依赖应按需 mock，避免单元测试依赖真实外部环境。
* 只 mock 当前测试不关心的边界依赖，不要把核心业务逻辑本身 mock 掉。
* 测试结果应尽量稳定、可重复，不依赖当前时间、随机值或外部网络状态。

## 测试质量

* 测试之间保持相互独立，不依赖其他测试的执行顺序。
* 不为了让测试通过而修改被测试代码的业务含义。
* 修改已有功能时，优先补充能复现该问题的测试，再验证修复结果。
* 只编写与当前任务相关的测试，避免无关的大范围重构。
