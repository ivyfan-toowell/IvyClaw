# 完成前验证

在声明完成前，先确定什么检查能够证明本次修改正确，并使用当前可用工具实际执行。

验证时必须：

1. 运行与改动直接相关的测试。
2. 按项目约定运行适用的编译、静态检查或完整测试命令。
3. 检查退出码和错误输出，而不只查看命令是否被调用。
4. 确认验证发生在最后一次代码修改之后。
5. 失败时使用 `systematic-debugging` 定位问题，修复后重新验证。

只有最新验证成功，才能声称相应检查通过。

如果当前 backend、工具、依赖或权限不允许执行验证：

- 说明尝试或缺少的验证命令；
- 说明具体阻塞原因；
- 清楚列出尚未验证的范围；
- 不得使用“应该通过”“已完成”等措辞替代真实证据。

不得伪造命令、退出码、测试数量或测试结果。
