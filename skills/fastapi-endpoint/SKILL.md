# FastAPI 接口编码规范

## 路由

* 使用 `APIRouter` 按资源拆分路由，保持与项目现有模块结构一致。
* 路径使用名词复数，例如 `/orders`、`/users`。
* 使用 HTTP 方法表达动作，不在 URL 中使用 `create`、`update`、`delete` 等 CRUD 动词。
* 单资源使用路径参数，例如 `/orders/{order_id}`；查询、过滤、分页使用 query 参数。
* 修改已有接口时，除非任务明确要求，否则不要破坏现有路径、方法和响应契约。

## 请求模型

* 结构化请求体使用 Pydantic 模型，禁止使用裸 `dict`。
* 创建、更新等不同用途按需要拆分模型。
* 明确必填、可选字段及必要的字段校验。
* 不允许客户端传入内部状态、审计字段或系统生成字段。

## 响应模型

* 使用 `response_model` 或等效方式显式声明响应结构。
* 对外响应使用 Pydantic 模型，不直接暴露 ORM 对象或内部数据结构。
* 只返回客户端需要的字段，避免泄露内部字段或敏感信息。
* 同类接口保持字段命名和返回结构一致。

## 错误处理

* 可预期的业务错误使用 `HTTPException` 或项目已有的统一异常机制。
* 使用正确的 `status_code` 和简洁、稳定的 `detail`。
* 不把 traceback、SQL 错误、文件路径、密钥等内部异常信息返回客户端。
* 未知异常保留服务端日志，不静默吞掉异常。

## 接口层职责

* 路由层只负责接收和校验输入、调用业务层、转换响应和映射 HTTP 错误。
* 不在路由函数中堆积复杂业务逻辑。
* 优先复用项目已有的 service、依赖注入、鉴权和异常处理机制。
* 只修改完成当前接口任务所必需的代码。
